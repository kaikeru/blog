# Blog Stack Update - Design

Date: 2026-10-20

## Goal

Make the blog build and deploy again on current, low-maintenance tooling while keeping Hugo, the custom `kaikeru` theme, the existing content, and the existing look. Hosting stays free (GitHub Pages) and the custom domain (`www.kaikeru.com`) is unchanged.

## Decisions

- Scope: modernize in place. No generator switch, no redesign.
- Analytics: dropped entirely.
- Deploy: GitHub Actions deploying to GitHub Pages from this repo.
- Twitter social link: removed.
- Syntax highlighting: Hugo's built-in Chroma replaces highlight.js.

## Current state

- Hugo last built against v0.51 (2018). Hugo is not installed locally.
- CI is `azure-pipelines.yml` on the retired `Ubuntu 16.04` image. It builds and pushes `public/` to `kaikeru/kaikeru.github.io` using a stored GitHub token.
- `googleAnalytics = "UA-81904592-1"` is Universal Analytics, shut down in 2023.
- Theme: `themes/kaikeru` (committed, not a submodule). Layouts: `baseof`, `single`, `list`, `index`, `404`, partials `head`, `header`, `footer`, `list-item`, `pagination`.
- Config enables highlight.js via `highlight`, `highlightStyle`, `highlightLanguages` params.

## Changes

1. **Hugo upgrade**
   - Install current Hugo extended locally (Homebrew) to build and verify.
   - Fix template breakage found at build time. Likely areas: deprecated `.Site.GoogleAnalytics`, `.Hugo`, `.Data.Pages`, `.URL`, `.Site.Author`, and the old `[author]` / `googleAnalytics` config keys.
2. **Config cleanup**
   - Remove `googleAnalytics`.
   - Remove the Twitter entry from `[[menu.social]]`.
   - Update the copyright year range.
   - Keep `config.toml` unless the current Hugo warns about it; renaming to `hugo.toml` is optional.
3. **Syntax highlighting**
   - Remove the highlight.js script/stylesheet includes from `themes/kaikeru/layouts/partials/head.html` (or wherever they are) and the `highlight*` params from config.
   - Enable Chroma via `[markup.highlight]` in config, with a style close to the current `atom-one-dark` (e.g. `onedark` or `monokai`), using CSS classes generated by `hugo gen chromastyles` into the theme stylesheet.
   - Verify existing code blocks in the posts (java, python, yaml, bash, dockerfile) render correctly, including fenced blocks without a language.
4. **Analytics removal**
   - Delete any analytics partial or include in the theme.
5. **Other theme assets**
   - Check Google Fonts, icon, and any other external references load over https; pin versions where applicable.
6. **CI and deploy**
   - Delete `azure-pipelines.yml`.
   - Add `.github/workflows/deploy.yml`: on push to `master`, check out, set up a pinned Hugo extended version, run `hugo --minify`, upload the Pages artifact, deploy with `actions/deploy-pages`. Also allow `workflow_dispatch`.
   - `static/CNAME` stays so the custom domain is preserved.
7. **Docs**
   - Update the README build pipeline section and the config.toml header comment.

## Manual steps for the owner

- In this repo's settings, set Pages source to "GitHub Actions".
- Move the custom domain to this repo's Pages site, then retire or archive `kaikeru/kaikeru.github.io`.
- Remove the old Azure pipeline and its stored GitHub token.

## Verification

- `hugo --minify` completes with no errors or deprecation warnings.
- `hugo server`: check the home page, a post with code blocks, the resume, the reading list, and the 404 page.
- Inspect `public/` for expected pages, `CNAME`, and `robots.txt`.
- Run the workflow on a branch (via `workflow_dispatch`) before relying on it from master.

## Risks

- Template removals across about 7 years of Hugo releases; discovered and fixed at build time.
- The deploy path can only be fully proven once pushed; mitigated by a branch run first.
- Chroma output will not be pixel-identical to highlight.js; the style choice is adjustable.

## Out of scope

- Theme redesign, new content, a different generator or host, or adding any analytics.
